# Disposable canary validation (candidate)

Run `node scripts/run-disposable-canaries.mjs` with Node 24, Docker, Supabase CLI 2.116.0, and installed repository dependencies. The GitHub workflow provisions the same prerequisites and runs manually or on pushes to the candidate branches. No hosted database or provider secrets are required.

The runner creates a unique temporary Supabase project, replays this checkout's migrations, and runs the AI dispatch, Sendillo inbound, Dialpad inbound/STOP, sequence tick/queue, enrollment, starter-library, simulation, and reliability integration suites. It also runs the dedicated egress-guard proof. A failed test or setup returns nonzero; cleanup failure also returns nonzero and preserves the temporary directory for investigation. Use a dedicated Docker runtime locally; `SANDRA_CANARY_DOCKER_HOST` may select a `unix:///` socket. Local API/SQL ports 54321/54322 must be available.

These are application regression checks with model stubs and the existing mock messaging provider. They do not prove live provider credentials, external delivery, production routing, or production availability. The fetch guard permits only `http://127.0.0.1:54321`, rejects redirects, and denies a provider request before the underlying fetch is called; it is not a kernel-level network firewall.

After local status is read, the runner prints one `[disposable-canary-manifest]` JSON record. It contains the candidate commit SHA, hashes of the copied migrations and source paths, the actual PostgreSQL `version()` and `transaction_isolation`, the actual `pg_get_indexdef` for the active sequence-step uniqueness index, disposable-project isolation, mock-provider mode, and the sequence clock contract. Generated API keys, service-role keys, JWT secrets, and database connection strings are captured in memory only and never printed. Missing source hashes, CLI-version mismatches, database metadata, or the critical index fail the manifest instead of being reported as production-equivalent.

The clock contract recorded by the manifest is the application `Date`/`Date.now()` for enrollment and tick scheduling, PostgreSQL `now()` for retry/resume scheduling and audit defaults, and PostgreSQL `least(coalesce(p_stale_before, now() - interval '15 minutes'), now() - interval '15 minutes')` for stale-claim reconciliation. Quiet-hours are `[08:00, 21:00)` local, the current direct quiet deferral is +10 hours, each tick reads 100 due enrollments and may inspect at most one additional 100-row retained-claim page, queued releases are capped at 240, the tick budget is 240000 ms, queue deferral is 30 minutes, and the cron cadence is five minutes. Fake timers in integration tests advance application time while real network timers remain live.

The runner's cleanup always invokes `supabase stop --no-backup` for its own temporary project and then removes its temporary directory. Hosted execution has not been certified. The candidate branches disable Vercel preview deployment. This harness does not remove scheduled scripts, authorize production mutations, or claim live-provider reliability.

The cancellation contract tests use fake command executables and cover startup/test interruption, including a child that ignores SIGTERM. They do not prove Docker teardown after SIGKILL, host loss, or an external cancellation deadline; the dedicated Docker runtime must be checked separately after a real run.
