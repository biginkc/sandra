# Inbox acceptance matrix

Baseline e5fce2d; implementation worktree 269d44ca. This matrix records requirements, not passing tests. See approved development plan for exact new behavior and feature gates.

**Harness (DoD#2 acceptance slice, lane2/acceptance-harness):** `Required verification` is authored spec text — the concrete, faithful pass condition derived from each row's Existing capability + Treatment, not invented product behavior. `Status` and `Evidence` for every row are written by the acceptance specs through `playwright.inbox-acceptance.config.ts`, reset to a known baseline at the START of every run (`e2e/inbox-acceptance/global-setup.ts`) and only flipped to `pass`/`fail` by a genuine outcome from THAT run — a row's Evidence links the per-run screenshot artifact under `test-results/inbox-acceptance-evidence/`, and stale outcomes cannot survive a later fail or skip. The checked-in statuses below are historical leads from an earlier owned-fixture run and are not release evidence: `release_gate.py` requires this matrix and `test-results/inbox-acceptance-results.json` to carry the exact current candidate SHA before any pass can count. Outbox rows exercise the unchanged `/messages?tab=outbox` regression boundary.
