# Local continuous candidate projector

This runs the existing bounded global worker against only the fixed, marked full-Auth synthetic database. It never connects to original T2 `postgres` or production, calls providers, executes actions, or changes the serving gate. Global claims are intentional: the candidate is an owned synthetic installation, and production projection also needs global progress.

`python3 experiments/inbox-candidate-worker/run.py --owned-fixture` drains one bounded worker round, then waits two seconds. An exclusive local lock prevents duplicate runners. The runner stops on a failed step; durable leases and generation fences remain intact. It is a local integration runner, not the final production service, pool sizing or throughput proof.

For a fixture assertion window, create this directory's `pause` file, wait until the last active step finishes, and coordinate with the owner before mutating. Remove the file to resume. Stopping the Python PID between rounds is also safe. Do not claim a stopped grant while a step is still active. `last-step.json` is operational state; successful source-to-Electric browser evidence belongs in the frontend proof.

The active preview now uses `services/inbox-projection-worker`, with one persistent PostgreSQL connection. `start-persistent.py` is a fixed-fixture, first-start launcher: it validates the database/container, creates a new dedicated synthetic LOGIN role and protected temporary credentials, pauses the Python comparison loop after its current round, then starts a nonroot sidecar in the database's network namespace. It refuses existing role/container names rather than overwriting them. Do not use it as a restart script, and do not print its temporary environment file.

`persistent-evidence.json` records that image's actual role restrictions and pool count; `persistent-live-evidence.json` records the real inbound-write → projected Unread → read acknowledgment → updated projected row loop. Historical Python evidence remains distinct. The source manifest records current package hashes, while historical runtime receipts retain their original image/source identity. The active sidecar has not yet been replaced with the later nonzero pool-error exit correction. Controlled rebuild/restart proof is pending, and the final combined worker must fit the single approved worker allocation.
