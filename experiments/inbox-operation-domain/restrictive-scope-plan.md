# Remaining restrictive effect boundary

The executable SMS opt-out operation (`opted_out`) differs from inbound STOP: it updates the selected property's outcome, opts its homeowner contact out of SMS, records consent and lead events, and permanently pauses active enrollments across properties linked to that contact. It does not establish a permanent property DNC lock or fan out by shared phone. Permanent `dnc` is separately gated by approved inventory A07 and must remain excluded with `permanent_dnc_not_enabled`. The canonical `properties_true_dnc_lock_guard` explicitly derives the permanent lock from `outreach_dispo='dnc'`; therefore treating that outcome as ordinary SMS suppression would be incorrect. Preserve this distinction.

Before enabling SMS opt-out, freeze the selected property's homeowner and exact linked-property/enrollment scope in authoritative preparation. Contact identity/policy/SMS consent revisions already exist. Add a persistent private per-contact scope revision advanced by property old/new homeowner linkage and enrollment old/new property linkage/status. Capture must be bounded per source row and handle nullable old/new keys; historical absence must fail closed until a guarded baseline exists. It must not scan all sibling properties in a trigger.

At effect time lock the current contact and bounded linked properties/enrollments in stable ID order, validate scope and policy revisions, and reject an over-limit scope before writes. Foreign-key and existing canonical guards must be verified as the serialization boundary for new property/enrollment insertion; otherwise add source-side locking. No snapshot count alone proves that concurrent insertion was excluded. Preserve whole-transaction retry for legacy writer lock inversions.

All property/follow-up/review, contact SMS flag, consent event, enrollment compliance stops, grouped sequence-paused events and immutable operation receipt must commit together. Repeated accepted steps use the durable step receipt and cannot append a second consent or lead event. A failure in any side effect rolls the entire effect back. Already opted-out and permanently locked contact history needs explicit canonical guard handling; never bypass DNC guards.

Actual tests required: two linked properties; selected/nonselected active enrollments; paused and terminal rows; contact already opted out; linked DNC property exact allowed compliance transition; cross-tenant neighbor exclusion; no homeowner; external homeowner reparent; concurrent enrollment insertion; contact scope reparent while waiting; consent failure rollback; replay; successor dependency handoff. Any unresolved scope or guard remains a denial, not a partial success.
