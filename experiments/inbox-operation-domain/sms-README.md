# Private canonical SMS opt-out follow-up

Depends on nonrestrictive domain PR #574, transitively #571/#565 and merged #568. These separate SQL files remain an owned-fixture candidate: no production migration, public execution grant, or enabled route.

`restrictive-apply.sql` permits only `opted_out` in addition to the tested nonrestrictive outcomes. `dnc` returns `permanent_dnc_not_enabled`: the canonical property trigger makes that a permanent lock, and approved A07 keeps it gated. Parsing an intent is not permission to execute it.

`restrictive-scope.sql` captures old/new contact property membership and enrollment changes with bounded per-row work. `restrictive-effect.sql` locks the scoped revision, contact, at most 500 linked properties and 500 active enrollments, checks the exact prepared sets and contact/consent policy, then applies SMS flag, append-only consent, active enrollment stops and lead events in the same fenced operation transaction. Preexisting paused rows are preserved to match the canonical manual opt-out coverage. A permanently locked contact remains immutable; a consent event still provides suppression and only the canonical compliance enrollment transition is used. Distinct sibling audit events have deterministic per-step/property source identities.

The guarded installer compares the previously tested domain body plus the actual canonical enrollment guard to exact source, and verifies an unconditional enabled BEFORE ROW INSERT/UPDATE/DELETE trigger. No guard is disabled. Historical scope baselines remain absent until an authoritative preparation implementation supplies them safely.

Actual runtime proof includes whole-effect rollback of contact/consent/enrollment/receipt, two sibling active stops, preserved paused enrollment, property outcome/review/follow-up, successor assignment, permanent-DNC denial and the prior conflict/replay checks. Three two-connection groups prove committed enrollment insertion changes the prepared scope, a later insertion waits for the effect transaction, and sibling homeowner reparent invalidates scope while the worker waits. Initial concurrency harness used an invalid ordinal; the core constraint rejected it, and the corrected harness creates fresh operations instead.

This does not prohibit every future active enrollment. An insertion serialized after opt-out can still become active; sender contact/consent eligibility must block its SMS. The separate future-enrollment and sender proof records this explicitly. Sender proof uses canonical exported fixture rows through production `sendSmsToContact`, with the provider registry stubbed and any provider send forbidden. It does not establish PostgREST transport or provider behavior.

Still required before public enablement: authoritative preparation/acceptance without fixture inputs, bounded historical baseline capture, independent review of the full helper, current-state API authorization, stable status/retry outcomes and worker dispatch. Additional canonical locked-sibling, missing-homeowner and cross-tenant exclusion cases should be added to the actual suite. Execution remains private until these boundaries are verified.


Shared homeowner safety is deduplicated by an immutable `(organization, accepted operation, contact)` receipt. It becomes reusable only with the source step's committed core receipt, exact equality of the original prepared contact policy/scope, and current shared post-state validation. Separate property outcomes still each receive their own fenced receipt. The actual two-property case passed with one consent event and one safety receipt; changing external contact policy or the original prepared scope still fails. `before-sharing/` and `upgrade-sharing.py` retain the exact previously tested helper bodies for the guarded fixture upgrade. Cross-property legacy lock inversions still require whole-transaction retry; no guard or conflict is ignored.
