# Policy version review

Root and independent reviewer inspected purpose separation, sorted old/new keys,
persistent rows without canonical deletion cascades, transaction rollback, private
function privileges, current consumers and evidence provenance. No scoped blocker
remains for this private source-capture building block.

Review led to strict namespace/key validation and real callable privilege-denial
checks. The current input runner checks installed trigger attachments and function
security metadata, in addition to the source-body comparisons. All three current
receipts match the SQL and their respective runners; the main receipt additionally
binds the field map. `verify_sources.py` enforces those bindings in CI.

The route and consent validation rules match the canonical suppression and consent
constraints. Ten source-behavior groups, three concurrency cases and five input/
privilege groups are recorded. Source hashes verify these recorded runs; running
the source verifier itself does not rerun the database tests.

Property state participates in quiet-hours policy, so a plain reply must depend on
the captured state revision even when no state variable appears in the message.
Outcome also clears follow-up time; a dependent assignment must consume the
revisions returned by the committed outcome step. Neither behavior permits using
projection generations as command authorization.

Historical and absent-policy baselines, complete session/global permission and
provider/template dependencies, current-time checks, canonical locking and durable
receipts remain required. The slice does not authorize a send, prove every legacy
writer can retry safely, or install a production migration. Prior source versions
and receipts remain explicitly named historical evidence.
