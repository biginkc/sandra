# Shared boundary read-only checker

Run `scripts/outbox-db-contract-readonly.mjs` with `DATABASE_URL` set to the session-pooler `postgres.<project-ref>` connection, `SUPABASE_ANON_KEY`, `--target shared-readonly` for TEST or `--target production` for Production, `--org <canary-org-uuid>`, `--phase pre|post`, `--api-url <matching project URL>`, `--platform-compare <sealed disposable db-contract/pre platform-config.json>`, `--catalog-compare <sealed disposable catalog-fingerprint catalog-pre.json>`, and `--output <new JSON path>`. Production also requires `INBOX_PROD_READONLY_ACK=copflsklaefwzipsrjqz`. A hosted POST check also requires `--pre-file` with the raw PRE output and `--plan-compare` with its sealed `readonly.json` beside `manifest.json`; the hashes and target must agree. The checker never takes a member session or service-role key. It uses SQL role switching inside one repeatable-read, read-only transaction and only two anonymous platform GETs. Hosted SQL connections require `NODE_EXTRA_CA_CERTS` to point to the Supabase Root 2021 CA with the committed DER SHA-256 fingerprint. Both the Node connection and catalog psql subprocess require verified TLS, hostname validation and TLSv1.2 or TLSv1.3. The output records client TLS protocol, cipher, leaf fingerprint, and the upstream `pg_stat_ssl` row as informational `upstream_hop_ssl`. That row describes the pooler-to-database hop and does not gate our client TLS result. Production use requires Jarrad to accept that the internal hop is unproven. `--probe-connection` checks TLS, read-only isolation and `SELECT 1` without querying application tables; it accepts only hosted targets and optionally writes `--output`.

For shared TEST, seal a passing output with `node scripts/inbox-ci/seal-shared-readonly.mjs --sha <tested-sha> --phase pre --output <readonly-output.json> --catalog-record <committed-catalog-run-directory> --platform-record <committed-db-contract-pre-run-directory>`. Run this from the clean evidence worktree at its current tip. The sealer reads both input artifacts from Git, verifies the output's comparison hashes, and writes only allowlisted verdicts and validated digests under the evidence root. Counts are omitted because the gate cannot recompute them from committed inputs. Commit that new run directory as a single-parent evidence-only commit. The sealer currently supports only the pre phase.

The catalog adapter imports `experiments/inbox-production-install/catalog_fingerprint.py` from the migrations branch after rebase. It asserts repeatable-read and read-only settings within the catalog tool's own transaction. Until that file and its manifest are present, a shared check fails with `CATALOG_TOOL_UNAVAILABLE`.

For local controls, start a uniquely named plain `postgres:17` container bound to loopback, load `readonly-local.sql`, and run `node --test --test-concurrency=1 scripts/outbox-db-contract-readonly.local.test.mjs` with the fixture's port. The fixture is synthetic and the test script only connects to `127.0.0.1`. It sets `enable_seqscan=off` for its tiny tables so policy controls reach the RLS oracle; hosted checks keep natural plans and reject only a same-target, per-role and per-shape Index/Bitmap-to-Seq regression on POST. Remove the container when finished.

A queued diff on shared TEST remains `INCONCLUSIVE` in `items.queued_invariants`, and two fresh observations five minutes apart must be identical before the top-level record can pass. A Production diff exits nonzero and needs a quiet-window rerun. Neither case reclassifies a changed row as invariant.
