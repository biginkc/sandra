# Shared boundary read-only checker

Run `scripts/outbox-db-contract-readonly.mjs` with `DATABASE_URL` set to the session-pooler `postgres.<project-ref>` connection, `SUPABASE_ANON_KEY`, `--target shared-readonly`, `--boundary test|production`, `--org <canary-org-uuid>`, `--phase pre|post`, `--api-url <matching project URL>`, `--platform-compare <disposable platform JSON>`, `--catalog`, and `--output <new JSON path>`. A post check also requires `--pre-file`, `--plan-compare`, and `--catalog-compare`. The checker never takes a member session or service-role key. It uses SQL role switching inside one repeatable-read, read-only transaction and only two anonymous platform GETs. The platform call expects the PostgREST version response header and GoTrue health `version`; missing version data fails the run.

The catalog adapter imports `experiments/inbox-production-install/catalog_fingerprint.py` from the migrations branch after rebase. It asserts repeatable-read and read-only settings within the catalog tool's own transaction. Until that file and its manifest are present, a shared check fails with `CATALOG_TOOL_UNAVAILABLE`.

For local controls, start a uniquely named plain `postgres:17` container bound to loopback, load `readonly-local.sql`, and run `node --test --test-concurrency=1 scripts/outbox-db-contract-readonly.local.test.mjs` with the fixture's port. The fixture is synthetic and the test script only connects to `127.0.0.1`. It sets `enable_seqscan=off` for its tiny tables so policy controls reach the RLS oracle; hosted checks retain the real planner and fail on a messages sequential scan. Remove the container when finished.

A queued diff on shared TEST remains `INCONCLUSIVE` in `items.queued_invariants`, and two fresh observations five minutes apart must be identical before the top-level record can pass. A Production diff exits nonzero and needs a quiet-window rerun. Neither case reclassifies a changed row as invariant.
