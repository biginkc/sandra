# Disabled fullscreen Inbox integration

`/inbox` and `/inbox/overview` are outside the dashboard layout. The existing controlled workspace occupies 100dvh with independently scrolling regions. Both routes call `notFound()` before creating any database client unless `INBOX_WORKSPACE_SERVER_ENABLED=1`. Existing Messages and Outbox entry points are unchanged.

The server obtains organization, user, session and access epoch from one canonical authenticated RPC. That identity keys the client mount. Missing schema or denied authorization fails closed; there is no invented tenant, service-role fallback or fixture response inside application routes.

The client creates immutable worksets using the v2 POST route, passes only their opaque scope/membership DTO to the Electric/TanStack DB adapter, and fetches independent work-filter counts concurrently. Loading counts never blocks overview entry. The overview uses a separate lightweight canonical context request with a maximum 15-second visibility lease, rechecks on tab resume, and hides/clears counts if authorization cannot be renewed. Network failure and confirmed revocation remain distinct; counts are not repeatedly scanned just to check access. Count failures have an independent retry control. Refresh and opaque next-page requests replace the server scope explicitly. Validated Electric DELETE messages explicitly invalidate selected/open identities and their detail cache; an empty page or transport reset never implies deletion. Selection survives view changes and pagination; review uses retained names for selected identities only, capped at 500. The review dialog supports focus management through the existing Dialog primitive.

TanStack Query 5.102.8 owns bounded, memory-only detail results and independent counts. Twenty recent conversation detail responses are retained with a 30-second freshness interval; one counts entry and ten operation receipt entries are permitted. The receipt capacity is prepared but no operation endpoint is called in this increment. Summary rows remain exclusively in TanStack DB. Access loss aborts requests and clears Query, all summary partitions, detail and selection. A real unmount closes the cache; React Strict Mode's immediate effect replay does not destroy its successor's cache.

Opening a known conversation fetches the actual read API. Selecting never fetches history. The mounted ConversationHistory component acknowledges only a matching rendered snapshot and uses the shared access-loss callback. Navigation generations reject late responses after close or replacement. Cached revisits do not bypass the component's canonical read-boundary checks.

## Verification and limits

RTL mounts the actual virtualized workspace, Query cache and ConversationHistory. Only the synchronization transport is replaced with deterministic snapshots. It verifies select/open separation, cached revisits, hidden selection removal, live access-denial clearing and a late detail after close. Page tests cover disabled-before-client and missing-schema behavior; overview tests cover entry while counts are pending. Query tests exercise eviction and cancellation rather than mirroring implementation.

This increment is not a complete Inbox release. Action preparation/acceptance/status, bulk replies, saved actions, unknown-sender detail, remaining individual tools, older history, new-arrival discovery, and actual outcome facets remain to be connected. The overview currently labels only work filters and does not present those counts as outcomes. No production flag or database configuration is enabled. End-to-end Next.js/browser validation against the real isolated SQL/Electric deployment remains required.
