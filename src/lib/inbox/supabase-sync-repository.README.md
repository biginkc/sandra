# Inbox workset HTTP integration

The two new routes are `/api/inbox/worksets` (POST) and `/api/inbox/sync/[scopeId]` (GET). Both return 404 before creating a client unless `INBOX_WORKSPACE_SERVER_ENABLED` is exactly `1`. No environment value is enabled by this change.

The request-scoped existing Supabase cookie client calls four agreed authenticated SQL wrappers: `inbox_authorize_sync(org_id)`, `inbox_create_workset(org_id, filter, limit, replaces_scope_id)`, `inbox_get_sync_scope(scope_id)`, and `inbox_bind_sync_handle(scope_id, partition_index, expected_handle, next_handle)`. SQL derives current user/session identity; no client actor arguments or service-role fallback are used. Missing schema or grants fail closed. The explicit TypeScript RPC extension must be replaced by regenerated schema types after the migration is installed.

The DB implementation currently exists only in the isolated canonical bridge fixture. Do not enable the routes until the reviewed migration, wrapper permissions, real PostgREST/JWT exercise and hosting prerequisites are satisfied. Sync additionally requires fixed private `INBOX_ELECTRIC_SHAPE_URL` and `INBOX_ELECTRIC_PROJECTION_TABLE` configuration. No browser SQL/table/where setting is accepted.

POST validates a 16 KiB request envelope, at most 500 rows and an optional `replacesScopeId` UUID. That UUID does not confer authority; SQL must atomically authorize same-organization, same-user, same-session replacement. Its response uses the existing client adapter scope DTO with ordered typed identities, never a provider token or arbitrary shape URL. Reauthorization and scope recheck happen after creation before responding.

This increment supports the canonical view filter only. Non-null cursors are explicitly rejected rather than silently treated as first-page requests. Full search, cursor pagination, filter parity, counts, freshness metadata and frontend page integration remain required work. Unit tests prove mapping and fail-closed boundaries; they do not prove deployed SQL permissions, real JWT authorization, Electric timing or performance targets.

Real Electric 1.8.1 rejected a single 500-target URL with HTTP 414. The implementation therefore slices each immutable ordered scope into at most five disjoint 100-target shapes. Durable handles are indexed by the server-validated partition; a client cannot supply membership. Every collection is cleared on replacement/revocation/expiry, and readiness remains loading until all partitions finish. The URL proof records five successful 100-row snapshots and 7,035 bytes for the longest admitted metadata request; hosted intermediary limits remain unverified.
