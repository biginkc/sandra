<objective>
Eliminate the hardcoded city-shaped market vocabulary from the application code: delete `KNOWN_MARKETS` and `WizardMarket`, switch the wizard, properties filter pill, and new-lead form to read counties from a server-side fetch, and update the CSV-ingest + lead-create write paths to set both `properties.market` AND `properties.county_id` together (per D-04). The CSV import path is async (server action enqueues a workflow that runs `processIngestChunk` later), so the county_id chosen at job-create time is persisted on `csv_imports.county_id` (column added by 043) AND threaded through the workflow params; the worker uses the workflow param as the hot path and falls back to re-reading `csv_imports.county_id` only if the param is missing (defensive recovery for jobs created before this plan ships).

Purpose: With migration 043 (CHECKs dropped + csv_imports.county_id added) merged, the application can finally write any market string AND has a persisted handoff for county_id across the async job boundary. This plan replaces the compile-time enum with a runtime data fetch, satisfies D-01 (counties is the source of truth), D-04 (synced text cache), D-06 (county picker replaces market picker), and D-07 (filter dropdown reads from counties). MARKET-02 + MARKET-04 are satisfied here.

The audit of `leads/kanban.tsx` and `leads/filter.ts` (the other surfaces called out in CONTEXT.md `<canonical_refs>`) confirmed both render `properties.market` as an opaque string with no comparisons against city-shaped values and no imports of `KnownMarket`/`WizardMarket`/`KNOWN_MARKETS` — so MARKET-04 needs no code change there. Acceptance criteria below include a grep that proves it stays that way.

Output: A typecheck-clean codebase where every market UI surface and write path goes through the counties table.
</objective>
