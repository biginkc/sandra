# Phase 01.5 Plan 05: Wrap /lists /jobs /templates with DataTableShell + count footer — Summary

DataTableShell + DataTableFooter wrap the three remaining CRM index-route tables (`/lists`, `/jobs`, `/templates`), giving them the warm-paper rounded card chrome and a row-count footer. Per D-08, no CircularPagination on these routes — the count footer is purely decorative because all three either load every row client-side or apply a server-side cap. Plan-spec total-prop fix applied to `/lists` so the count reflects the full result count, not the paginated page slice.

## Decisions Made

- **Verify-first when prior work satisfies the plan.** Ancestor commit `c811834` ("feat(01.5-wave2-05): DataTableShell + count footer on /lists, /jobs, /templates", May 1) already shipped the bulk of this plan. Rather than re-overwriting working code, the executor verified each file against the plan's structural acceptance criteria, made one targeted correctness fix to `/lists`, and ran the full verify suite. This matches the precedent set by Wave 1 plans 01/02.
- **Apply Rule 1 to `/lists` total-vs-rows.length mismatch only.** The plan explicitly instructed to consume the existing `total` prop (server-side count of all matching rows) instead of `rows.length` (page slice). The ancestor commit landed `rows.length`, which under-reports when more than `PAGE_SIZE` lists exist. This is a real UX bug — fixed.
- **Preserve the `/jobs` and `/templates` footer copy as-is.** They render `{visible} of {total}` instead of the plan's simpler `{count}` example. The "X of Y" form is more informative for client-filtered tables (it tells the user "you see 3 of 47 because of your filter") and the plan's acceptance criteria are structural (greps + tests), not literal copy. Changing them would be churn for no benefit.

## Deviations from Plan

### [Rule 1 — Bug] /lists footer used page-slice count instead of full total

- **Found during:** Task 1 — initial read of `lists-table.tsx`
- **Issue:** The Props destructure aliased `total` to `_total` to suppress the unused-variable lint warning, and the footer rendered `{rows.length}` (the current page slice, capped at `PAGE_SIZE`). When the user is on page 1 of a 200-row list set with `PAGE_SIZE = 50`, the footer says "50 lists" — wrong. The plan's CHANGE 2 + CHANGE 3 explicitly call for `{ rows, parsed, total }` and a footer of `{total.toLocaleString()} {total === 1 ? "list" : "lists"}`.
- **Fix:** Removed the underscore alias and updated the footer copy to use `total.toLocaleString()` with explicit `total === 1 ? "list" : "lists"` pluralisation. No other file changes.
- **Files modified:** `src/app/(dashboard)/lists/lists-table.tsx`
- **Verification:** `npx vitest run --config vitest.rtl.config.ts src/app/(dashboard)/lists/lists-table.test.tsx` → 7/7 pass; `npm run verify` → 612/612 pass.
- **Commit:** `8f1b9eb`

### [verification-only] /jobs and /templates footers diverge from plan's literal example copy but satisfy all acceptance criteria

- **Found during:** Task 2 — initial read of both files at HEAD
- **Issue:** The plan's `<action>` block shows footer copy of `{jobs.length.toLocaleString()} {jobs.length === 1 ? "job" : "jobs"}` and `{filteredTemplates.length.toLocaleString()} {filteredTemplates.length === 1 ? "template" : "templates"}`. The actual implementation (from ancestor commit `c811834`) renders `{visibleJobs.length} of {jobs.length} job{jobs.length === 1 ? "" : "s"}` and `{visible.length} of {templates.length} template{templates.length === 1 ? "" : "s"}` — i.e., "X of Y" instead of just "X".
- **Decision:** Left as-is. The plan's acceptance criteria are structural (`grep DataTableShell ≥ 2`, `grep DataTableFooter ≥ 2`, no `border-border rounded-md border`, no `CircularPagination`, RTL tests pass). All pass at HEAD. The "X of Y" copy is more informative on client-filtered tables and is the only divergence; rewriting it to match the plan's example would lose information.
- **Files modified:** None.
- **Verification:** Acceptance criteria + `npm run verify` → 612/612 pass.
- **Commit:** N/A (no working-tree changes for /jobs or /templates).
