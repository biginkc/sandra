# Phase 01.5 Plan 04: ProspectsTable retrofit — explicit page + totalPages contract

**ProspectsTable now accepts `page` + `totalPages` as required props (server-rendered, authoritative), satisfying the Plan 01.5-04 prop contract on top of the wave2-04 visual retrofit that had previously shipped via ancestor commit `04a2c22`.**

## Accomplishments

- Added `page: number` and `totalPages: number` as required props on `<ProspectsTable />` per the plan's literal interface contract
- `<CircularPagination currentPage={page} />` now uses the server-passed `page` (the same value the URL `?page=` parameter resolves to server-side) instead of `ts.page` (the client hook's local read)
- `page.tsx` passes `page={page}` and `totalPages={totalPages}` alongside the existing `total`/`pageSize` props

## Files Created/Modified

- `src/app/(dashboard)/properties/prospects-table.tsx` — added `page` and `totalPages` to `Props`; destructured them in the component signature; replaced the internal `const totalPages = Math.max(1, Math.ceil(total / pageSize))` with the prop value; updated `<CircularPagination currentPage={page}>` to use the server-passed value
- `src/app/(dashboard)/properties/prospects-table.test.tsx` — added `page={1} totalPages={28}` to the `renderTable` helper and to all 10 inline `<ProspectsTable />` renders across the existing test suites
- `src/app/(dashboard)/properties/page.tsx` — added `page={page}` and `totalPages={totalPages}` to the `<ProspectsTable />` call (both values are already locals from the existing query function)

## Decisions Made

- **Retain `pageSize` prop.** `SelectAllBanner` uses it for the `total <= pageSize` gate and the per-page selection caption. The plan adds `page` + `totalPages` as **new** props; it does not require removing `pageSize`. Removing it would break the cross-page select-all banner (and its associated RTL tests). Decision: additive, not replacement.
- **Keep the existing 'Showing X–Y of Z' footer copy.** The plan's example uses `{total.toLocaleString()} properties`. The current copy ("Showing X–Y of Z" — already shipped in `04a2c22`) is strictly more informative for the same total. The plan does not specify "remove the showingFrom/showingTo display"; treated the example as a minimum, not a maximum.
- **Combined Task 1 + Task 2 into one commit.** Task 1 makes `page` + `totalPages` required, but the only call site is `page.tsx` (Task 2 territory). Committing Task 1 alone would leave HEAD with a TypeScript error. Combined into one commit so HEAD remains green at every commit boundary.
