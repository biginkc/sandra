## Implementation Decisions

### D-01 — Token source: sibling repo, file: reference
- Package name: `@sandra/tokens`, version `0.1.0`
- Source path: `../Sandra Design System/` (sibling repo, NOT npm)
- Add to `package.json`: `"@sandra/tokens": "file:../Sandra Design System"`
- Exports: `./theme.css` → `tokens/theme.css`

### D-02 — globals.css: import token file, remove local :root block
- Add `@import "@sandra/tokens/theme.css";` after line 3 (`@import "shadcn/tailwind.css";`)
- Remove the full `:root { ... }` warm-paper token block that starts at line 70
- No competing definitions after this change

### D-03 — Registry components: copy files directly (not npx shadcn add)
- Copy from `../Sandra Design System/registry/` to `src/components/ui/`
- 3 files to copy:
  1. `search-input-pill/search-input-pill.tsx` → `src/components/ui/search-input-pill.tsx`
  2. `data-table-shell/data-table-shell.tsx` → `src/components/ui/data-table-shell.tsx`
  3. `circular-pagination/circular-pagination.tsx` → `src/components/ui/circular-pagination.tsx`

### D-04 — SearchInputPill interface (no X button inside)
- Props: extends `InputHTMLAttributes<HTMLInputElement>` + optional `wrapperClassName?` + `iconClassName?`
- Renders: `<div relative w-full>` wrapper + `<Search>` icon absolute left-4 + `<input pl-12 pr-4 rounded-full bg-secondary>`
- **No built-in X clear button** — the X must stay in TableToolbarSearch's outer wrapper div
- Usage swap: replace `<Input className="...rounded-full...">` + manual `<Search>` icon with `<SearchInputPill ref={inputRef} defaultValue={ctx.search} onChange={...} placeholder={...} aria-label={...} data-testid={...} />`
- Keep existing X clear button wrapper div in TableToolbarSearch (sits at absolute right-3)

### D-05 — DataTableShell + DataTableFooter interface
- Both exported from `src/components/ui/data-table-shell.tsx`
- `DataTableShell`: wraps `<div overflow-hidden rounded-2xl border border-border bg-card>`
- `DataTableFooter`: `<div flex flex-wrap items-center justify-between gap-3 border-t bg-muted/50 px-6 py-4>`

### D-06 — CircularPagination interface
- Props: `currentPage: number`, `totalPages: number`, `onPageChange: (page: number) => void`, `siblingCount?: number`
- Circular page buttons + chevrons

### D-07 — /properties: full pagination (DataTableShell + DataTableFooter + CircularPagination)
- File: `prospects-table.tsx` (1181 lines)
- Already has `total: number` prop and pagination URL state from Phase 1
- Wrap table in `<DataTableShell>`
- Add `<DataTableFooter>` with: count text + `<CircularPagination currentPage={page} totalPages={Math.ceil(total/pageSize)} onPageChange={...} />`
- URL-state behavior from Phase 1 preserved exactly

### D-08 — /lists, /jobs, /templates: count-only footer (no live pagination)
- `/lists` (`lists-table.tsx`, 250 lines): all lists loaded client-side — DataTableShell + DataTableFooter with count text only; pagination decorative
- `/jobs` (`jobs-list.tsx`, 618 lines): realtime 50-row cap — ?page= is decorative; DataTableShell + DataTableFooter with count text only
- `/templates` (`templates-list.tsx`, 368 lines): all prefetched client-side — DataTableShell + DataTableFooter with count text only

### D-09 — TableToolbarSearch: call-site signature unchanged
- Only the inner primitive swaps (bare Input → SearchInputPill)
- All existing props (ariaLabel, placeholder, testId, className) remain at the call-site level

### Claude's Discretion
- Exact import paths for the copied registry components
- Whether to add named exports or default exports
- Tailwind class ordering in the copied component files
- RTL test updates if any existing test assertions check for the bare `<input>` vs `<SearchInputPill>` wrapper
