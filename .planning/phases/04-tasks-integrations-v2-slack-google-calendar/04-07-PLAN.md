<gotchas>
- Pitfall 1: `chat.postMessage` to a user requires `im:write` + `conversations.open(users: <slack_user_id>)` first to obtain the DM channel id. Don't pass the bare user id as channel.
- Pitfall 6: Slack interactivity payload is `application/x-www-form-urlencoded` with a single `payload` field whose value is JSON. Use `URLSearchParams` to extract, then JSON.parse.
- Pitfall 7: ALWAYS read `await request.text()` first (raw body for HMAC); JSON re-stringify breaks the signature.
- Pitfall 8: chat.update needs `payload.message?.ts ?? payload.container?.message_ts`. Use both fallbacks.
- Pitfall 9: `after()` lifetime is bounded by `maxDuration` (300s default on Vercel Pro). Our two outbound calls (~1-2s) are fine.
- Slack 3-second ack: the webhook MUST return 200 within 3 seconds. Real work goes inside `after()`.
- Map Slack user → Sandra user via `user_oauth_tokens.external_account_id` (set by Plan 05's callback). The lookup query: `from user_oauth_tokens select user_id where provider='slack' and external_account_id = <slack_user_id>`. RLS doesn't block this when called from service-role.
- Authorization check in completeTaskFromSlack: tasks.assignee_id MUST equal the Sandra user_id resolved from the Slack user. Otherwise reject — prevents user A from clicking Mark Done on user B's task in a shared channel scenario (DM-only today, but defense-in-depth).
- The bot token used for chat.postMessage is the assignee's bot token (the Sandra user receiving the DM). chat.update uses the SAME bot token — store it via getDecryptedToken at update time. Map back via tasks.assignee_id → user_oauth_tokens for the assignee.
</gotchas>
