# My Leads desktop stress-test rerun — 2026-09-12

## Result

The second desktop stress campaign completed against the latest merged candidate (`a9021cfe`, `fix(my-leads): close desktop stress-test workflow gaps`) in a local production build. No new reproducible product defect was found, and no source changes were required during this rerun.

The initial browser trouble was an environment mismatch. The candidate was first served with `next dev` on port `58701`. The page shell loaded, but React interactions were inert in both the in-app browser and an independent Chromium check. The console showed rejected cross-origin HMR and font requests from `127.0.0.1`; the HMR connection also returned an invalid response. Serving the same candidate with `next start` after a clean production build on port `58702` restored client behavior. Stage toggles, search, date controls, modal flows, and navigation controls then worked. This separates the dev-server transport failure from a My Leads regression.

## Scope and safety

- Desktop viewport only; mobile is out of scope for this campaign.
- Synthetic local Supabase identities only: owner, rep, and two unauthorized identities.
- No Maria account, live provider, production write, or external call was used.
- `Start call` was checked as a disabled-provider guard and did not invoke a provider.
- Existing production server on port `58700` and other worktrees/sessions were left untouched.
